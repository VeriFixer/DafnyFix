# DafnyFix: Single-Transformation Automated Repair in Dafny

DafnyFix is an automated program repair tool for fixing Dafny verification failures caused by implementation errors. It adopts a deterministic approach that searches over a space of candidate patches generated through a group of complementary heuristics:
- Code mutation using [MutDafny's](https://github.com/MutDafny/mutdafny) mutation operators,
- Reversed variants of some mutation operators,
- Repair templates guided by faulty program states.

## Repository Structure

- [repair/](./repair/) : the main source code for candidate patch generation, built on top of MutDafny's source code
- [dafny/](https://github.com/isabel-amaral/dafny/tree/478b98d951240ac67da5f23ffaefe0a6466bce6a) : submodule of our dafny fork
- [verifixer_fault_localization/](https://github.com/VeriFixer/verifixer_fault_localization/tree/00aa4879c3423f2e09831cb36e73523b7860fc95) : submodule of the fault localization implementation we adopt for guiding our search
- [dataset/dafny-synthesis-refined/](./dataset/dafny-synthesis-refined/) : dataset of [dafny-synthesis](https://github.com/Mondego/dafny-synthesis) programs with implementation errors, refined to have complete specifications
- [dataset/repairs/](./dataset/repairs/) : repairs generated by our pipeline for our dataset
- [run.sh](./run.sh) : script that implements the patch search pipeline
- [gen-jobs.sh](./gen-jobs.sh) and [run-jobs.sh](./run-jobs.sh) : paralelization scripts

## Running the Project

To simplify setup, we provide a [Docker](https://docs.docker.com/engine/install/) environment with a ready-to-use Dockerfile that installs .NET, Dafny, Z3, Python dependencies, and builds all external tools.

1. **Build the Docker image**
```shell
docker build -t dafny_research:latest .
```

2. **Run the interactive container**

**Base container.** Start an interactive shell in the pre-configured environment.

```shell
docker run --rm -it -w /app dafny_research:latest bash
```

**Generated data.** Mount the `repairs` and `jobs` directories to your local machine so that files generated while running the project are accessible and persisted after the container exits.

```shell
docker run --rm -it \
  -v "$(pwd)/repairs:/app/repairs:delegated" \
  -v "$(pwd)/jobs:/app/jobs:delegated" \
  -w /app \
  dafny_research:latest bash
```

**Development.** Mount the project source files and directories into the container. This allows changes made locally to be immediately available inside the container without rebuilding the image.

```shell
docker run --rm -it \
  -v "$(pwd)/run.sh:/app/run.sh:delegated" \
  -v "$(pwd)/gen-jobs.sh:/app/gen-jobs.sh:delegated" \
  -v "$(pwd)/run-jobs.sh:/app/run-jobs.sh:delegated" \
  -v "$(pwd)/repair:/app/repair:delegated" \
  -v "$(pwd)/verifixer_fault_localization/src:/app/verifixer_fault_localization/src:delegated" \
  -v "$(pwd)/verifixer_fault_localization/strategies:/app/verifixer_fault_localization/strategies:delegated" \
  -v "$(pwd)/dataset:/app/dataset:delegated" \
  -v "$(pwd)/repairs:/app/repairs:delegated" \
  -v "$(pwd)/jobs:/app/jobs:delegated" \
  -v "$(pwd)/original:/app/original:delegated" \
  -w /app \
  dafny_research:latest bash
```

3. **Run DafnyFix**

3.1. **On a single file**

```
bash run.sh <full path to the program under repair, e.g., ./dataset/abs.dfy> 
    [--min_lines <the minimum number of faulty lines to explore, e.g., 5 (by default)>]
    [--min_states <the minimum number of faulty program states to explore, e.g., 10 (by default)>]
    [help]
```

3.2. **On multiple files in parallel**
```
bash gen-jobs.sh <full path to the folder with the base dataset, e.g., ./dataset> 
   [--min_lines <the minimum number of faulty lines to explore, e.g., 5 (by default)>]
   [--min_states <the minimum number of faulty program states to explore, e.g., 10 (by default)>]
   [help]

bash run-jobs.sh
```
**Note**: Requires [GNU Parallel](https://www.gnu.org/software/parallel/).
